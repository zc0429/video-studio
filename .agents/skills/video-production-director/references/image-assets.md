# Generated images as film assets / v1.5

Load this only when image generation/editing or generated still assets are relevant. It is a production workflow, not a model, installation or claim that any particular service is connected. Preserve the user's final-review delegation and existing budget.

## 1. Choose the route for the story

Use generated images for original style frames, character/object identity, environments, textures and key shot assets where they fit. Don't choose all-geometric code animation merely because code is controllable; don't use generation when precise geometry, a real product or typography is better served by other tools. Decide how each asset will participate in an actual shot before making a large collection of pictures.

Discover the current host's actual image tool/service catalog, applicable skills and documented inputs. A local binary probe cannot establish access to a hosted model. Record the real tool/provider, exposed model/version, inputs, output mechanism, usage terms, available quota and incremental charges in the project resource register. If something is not exposed, mark it unknown; do not invent a model name, seed or capability. Never infer this environment's access from an old conversation or a GitHub link.

Prefer an available authorized host tool or existing reviewed workflow. Follow its current schema and instructions, including reference-image handling and transparency. For image edits, inspect the target and use the appropriate image-editing capability; don't pretend unrelated procedural output is an edit. Don't install models, buy subscriptions or start newly billed API work merely because this reference was loaded.

## 2. Lock identity before generating a sequence

Use the selected art direction and create a small set of purposeful candidates. Solve composition, object proportions, costume, material and light before motion. Review actual images; choose under the user's delegation and record `self_reviewed`, rather than inventing personal user approval.

Persist the accepted reference files and their hashes. Reuse them using controls actually supported by the chosen model; don't assume a model supports multiple references, fixed seeds, inpainting, pose/depth or first/last-frame constraints. Preserve model/prompt/parameters when available, including which fields are not exposed. Avoid redefining the whole subject from scratch in each shot.

Use `assets/IMAGE_ASSET.json` per accepted asset, or an equivalent project register. Link references, source/usage basis, intended shot, actual file, variant decision and motion plan. Keep precise editable titles/subtitles in the controlled composition layer. An image is not accepted solely because it looks attractive in isolation: compare adjacent shots and the story's visual change.

## 3. Give the image a shot-level motion plan

- **Image-to-video:** only when the actual service, required reference controls, source cadence and budget are available; test identity and action before expansion.
- **Layered 2.5D:** separate meaningful foreground/subject/background when feasible, repair occlusion gaps and animate intentional depth/light/action. Check newly revealed areas and avoid treating every shot as the same pan/zoom.
- **3D/hybrid:** use generated images as reviewed design/texture references and build geometry/camera for actions requiring precise spatial control or product identity.
- **Static shot:** only when a deliberate hold serves the story. It must not substitute for an unavailable action or be stretched merely to hit a target duration.

Use an available viable alternative if a route fails. If the story cannot be achieved within actual capability or budget, state the concrete limitation instead of silently replacing it with a slideshow or calling an unfinished sample a film. Two failed controlled candidates trigger diagnosis of identity, action, reference fit or tool choice; log costs and reuse accepted parts.

## 4. Time and assemble the film

Duration comes from measured narration, visual beats, pauses and the full animatic. A still image itself has no motion frame rate. Camera/object motion computed at 60fps in a composition can be native rendered motion, but it does not mean the image model generated 60fps footage. Lower-cadence generated video requires a recorded conversion method; never use container fps as proof of native generation.

Compose picture, motion, editable text and sound on a controllable timeline, then inspect continuous motion, transitions, identity, edge/alpha artifacts, text timing and audio as tools permit. Verify the selected duration, 60fps constant-frame-rate output, decoded frame count and any required audio. Technical checks do not establish aesthetic success or replace actual inspection.

## 5. Fees, reuse and persistence

Set `generation.enabled=true` when a production route actually uses generation; explicitly classify `requires_paid_jobs` from the actual service/account terms. Existing authorized included quota is different from newly billed work; unknown price/access is not “free.” Save known costs without inventing a price. Do not repeatedly ask for permission already granted, and do not run new paid jobs without their budget basis.

Store generated assets and source manifests in the project or an authorized recoverable storage channel, not as an unexplained prompt-only result. Rights, provenance and disclosure follow the actual model terms and publication context. Don't put credentials, model weights or a large image collection into the shared skill prompt. Reusable accepted assets stay indexed; don't auto-load or regenerate everything for every film.
